# Healper — 기획 초안 v0.1

> 운동·식단을 하면 캐릭터가 강해지고, 강해진 캐릭터가 스테이지를 깨서 재화를 벌고,
> 그 재화로 운동·식단을 더 잘하게 해주는 기능을 해금하는 **선순환 구조의 게임**.

작성일: 2026-08-08 · 상태: 초안(미확정 항목은 §10 참조)

---

## 1. 한 줄 정의

**현실의 운동·식단이 유일한 연료인 방치형 육성 게임.**
게임 안에서 번 것은 다시 현실의 운동·식단을 돕는 데 쓰인다.

### 설계 대전제 (모든 결정의 상위 규칙)

1. **진행도는 오직 몸으로만 산다.** 돈으로는 편의와 꾸밈만 산다.
2. **앱의 하한선은 게임과 무관하게 지킨다.** 기록·알림·연동은 Day 1부터 무료.
3. **식단은 "빼는 게임"이 아니라 "채우는 게임"이다.** (§7 참조)

## 2. 확정 사항 (결정 로그)

| # | 항목 | 결정 | 근거 |
|---|---|---|---|
| D1 | 장르 | **방치형 오토배틀러 + 짐 타이쿤 하이브리드** | 세션 짧고(30초~2분) 재화 싱크가 자연스러움 |
| D2 | 포인트 구조 | **단일 재화(코인) + 파생 3스탯** | 밸런싱 부담 최소, 행동 피드백은 확보 |
| D3 | 스탯 종류 | 근력 / 지구력 / 컨디션 | 운동 2축 + 식단 1축 |
| D4 | 기능 해금 범위 | **편의·심화 기능만** | 핵심 기능 게이팅 시 신규 이탈 |
| D5 | 기술 스택 | **Unity** | 게임 연출·밸런싱 툴 우선. 헬스 연동은 네이티브 플러그인으로 해결 |
| D6 | BM 원칙 | P2W 전면 배제 | 컨셉 자살 방지 |
| D7 | 타깃 유저 | **초중급 (운동 3~12개월차)** | 아래 §2.1 |

### 2.1 타깃 유저 (D7)

**운동을 시작했지만 아직 습관이 안 붙은 사람.** 헬스 3~12개월차, 현재 주 2~3회,
목표는 주 4회로 끌어올리는 것.

초심자도 상급자도 아닌 이 구간을 고른 이유는 셋이다.

1. **게임화 동기가 실재한다.** 이미 주 5회 하는 사람은 게임이 없어도 한다.
   반대로 완전 초심자는 기록할 데이터 자체가 없다.
2. **§7.3 ②(보상 자기교정)가 이 구간에서만 성립한다.** 중량·볼륨을 기록할 줄
   알아야 "거짓 입력 -> 불가능한 프로그램 처방 -> 즉시 들통"이 작동한다.
3. **§5.1 해금 기능이 이 구간에 맞는다.** 초심자에게 디로드 제안은 무의미하고,
   상급자에게 폼 가이드는 이미 아는 내용이다.

이 결정이 밸런싱 숫자의 근거가 된다. 주간 목표 4회, 한 세션 볼륨 상한 15,000
(초중급 상단), 유산소 부하 상한 90 모두 이 구간 기준이다.

> 뒤집기 쉽다. 숫자는 전부 `src/Healper.Core/Balance.cs` 한 곳에 있다.

## 4. 포인트 · 스탯 시스템

### 4.1 코인 (단일 재화)

모든 활동이 코인으로 합류한다. 게임 진행·구매의 유일한 소프트 통화.

```
코인 획득 = Σ(활동별 기본값) × 기록신뢰도 × 일일캡
```

### 4.2 스탯 3종 (파생)

| 스탯 | 인풋 | 산식(초안) | 전투 역할 |
|---|---|---|---|
| **근력** | 웨이트·저항운동 | 볼륨 = 중량 × 횟수 × 세트 | 공격력 |
| **지구력** | 유산소 | 시간 × 강도(HR존 or METs) | 스테이지 지속시간 / 행동 횟수 |
| **컨디션** | 식단 | 기록여부 + 단백질목표 + 끼니 규칙성 | 체력 회복 · **오프라인 진행 속도** |

> **왜 컨디션이 오프라인 진행 속도인가:** 식단은 매일 하는 행동이라 "매일 접속"과 결이 맞는다.
> 반대로 근력·지구력은 주 3~4회라 순간 전투력에 매핑하는 게 자연스럽다.

### 4.3 스탯을 3개로 제한한 이유

Habitica는 4스탯(STR/INT/CON/PER) 자동 배분이 실제 수행 태스크를 반영하지 못한다는 불만이
장기 이슈로 남아 있다([이슈 #8172](https://github.com/HabitRPG/habitica/issues/8172)).
**스탯을 잘게 쪼갤수록 인과가 흐려지고, 유저는 게임 수치를 위해 운동을 왜곡한다.**

### 4.4 오프라인 진행 공식 ★핵심

```
오프라인 획득량 = 기본치 × 최근7일이행률(0.2 ~ 2.0) × 시설배수
```

- 운동을 안 해도 **0.2배는 쌓인다.** 복귀 유인을 남기기 위함.
- 진행도를 0으로 만들거나 회수하는 설계는 **금지.** 진행 상실은 이탈의 최대 원인.
- 꾸준한 유저와 방치 유저 사이에 **최대 10배 격차**가 나도록 튜닝.

## 5. 재화 & 경제

| 재화 | 획득 | 사용처 | 성격 |
|---|---|---|---|
| **코인** (소프트) | 매 활동 · 스테이지 | 스탯 강화, 장비, 시설 레벨업 | 무한 인플레 싱크 |
| **결정** (하드) | 주간목표 · 업적 · 스테이지 최초 클리어 | **기능 해금**, 시설 티어업 | 희소 · 의미 있는 선택 |
| **패스 포인트** | 시즌 진행도 | 시즌 보상 트랙 | 중기 목표 |

### 5.1 무료 vs 해금 경계선 (D4)

| 절대 무료 (Day 1) | 재화로 해금 |
|---|---|
| 운동·식단 기록, 히스토리 | AI 사진 식단 인식 |
| 기본 루틴 1~2개 | 루틴 템플릿 슬롯 확장 (3 → 10) |
| 알림, 기본 통계 | 주간 심층 리포트 / 스탯 상관분석 |
| 헬스 앱 연동 | 프로그램 자동 생성(점진적 과부하) |
| 캐릭터 기본 외형 | 운동 폼 가이드 · 스킨 · 짐 테마 |

### 5.2 프레스티지

게임 진행도는 리셋하되 **현실 활동 기록은 절대 리셋하지 않는다.**
프레스티지 보상 = "현실 이행률 → 게임 배수" 계수의 영구 상승.

## 6. 게임 구조: 방치형 + 짐 타이쿤

### 6.1 방치형 오토배틀러 (코어)

- 스테이지 자동 진행. 유저는 스탯·장비만 관리.
- 스탯이 곧 전투력이라 **"어제 유산소를 빼먹어서 못 깼다"는** 인과가 즉시 보인다.

### 6.2 짐 타이쿤 (재화 싱크 + 해금 레이어)

시설을 지으면 **게임 내 버프 + 현실 기능 해금**을 동시에 준다.

| 시설 예시 | 게임 효과 | 현실 효과 |
|---|---|---|
| 웨이트 존 | 근력 계수 ↑ | 루틴 슬롯 확장 |
| 유산소 존 | 지구력 계수 ↑ | HR존 분석 리포트 |
| 주방 | 컨디션 계수 ↑ | AI 사진 식단 인식 |
| 분석실 | 오프라인 배수 ↑ | 주간 심층 리포트 |

> ⚠️ **미해결:** 시설 보상이 "시각적 즐거움"에 그치지 않고 **실질적으로 생활에 도움이 되도록**
> 만드는 것이 요구사항. 위 표는 자리표시자이며 §10-Q1에서 별도 아이디어 세션 필요.

### 6.3 주간 레이드 (선택, P4)

주간 운동 목표 달성 시 입장권 지급 → 로그라이트 던전런.
"이번 주 목표를 채워야 들어갈 수 있다"는 압력을 만든다.

## 7. 안전 가드레일 ★타협 불가

### 7.1 섭식장애 리스크 차단

2026년 보도와 [BJPsych Open 연구](https://www.cambridge.org/core/journals/bjpsych-open/article/effects-of-diet-and-fitness-apps-on-eating-disorder-behaviours-qualitative-study/2D1EE739D97AB3EFC6573835E4C527BD)는
칼로리 게이미피케이션이 섭식장애 행동을 강화한다고 지적한다.
참가자들은 "앱과 덜 먹기 경쟁을 하게 됐다"고 진술했고,
초록/빨강 진행바가 수치심 → 폭식으로 이어졌다.

**금지**
- ❌ 칼로리 적자가 클수록 재화 많이 지급
- ❌ 목표 칼로리 초과 시 재화 차감 / 캐릭터 데미지
- ❌ 식단 스트릭 끊김 페널티

**대체**
- ✅ **기록 자체**에 기본 보상 (먹은 게 무엇이든)
- ✅ 단백질·식이섬유 등 **"채우는" 목표** 달성 시 보너스
- ✅ 끼니 거르지 않음(규칙성)에 보너스, 과소섭취는 오히려 감점
- ✅ **일일 상한(캡)** — "더 극단적으로 하면 더 받는다"를 원천 차단

### 7.2 데이터 신뢰 / 치팅 방어

표준 만보계 알고리즘은 물리적 흔들기에 대부분 뚫린다.
다행히 HealthKit / Health Connect는 `recordingMethod`로
**수동 입력 / 자동 기록 / 실시간 측정**을 구분해 준다.

| 기록 방식 | 재화 지급률 | 비고 |
|---|---|---|
| 실시간 측정 (ACTIVELY_RECORDED) | 100% | |
| 자동 기록 (AUTOMATIC) | 100% | |
| 수동 입력 (MANUAL) | **30% + 일일 캡** | 정직한 유저도 쓰므로 0%는 금지 |

추가: 비현실적 볼륨·속도 이상치 탐지, 하루 총 획득량 하드캡.

> **타이밍:** 돈이 걸리기 전엔 아무도 치팅하지 않는다. 그러나 BM(P5)이 붙는 순간 시작된다.
> 따라서 **P6은 P5보다 먼저, 최소한의 형태로라도** 존재해야 한다.

### 7.3 입력 신뢰 설계

운동·식단은 자기 신고 데이터라, 하지 않고 입력해도 시스템은 받아들인다.
이 문제는 하나가 아니라 **두 개**이고, 섞어서 접근하면 설계가 망가진다.

| | 위협 A: 자기기만 | 위협 B: 외부 보상 부정 |
|---|---|---|
| 상황 | 혼자 플레이, 랭킹·현금 없음 | 리더보드, 길드, 광고 수익 |
| 누가 손해? | **본인뿐** | 다른 유저, 서비스 |
| 유인 | 약함 | 강함 (봇까지 등장) |
| 대응 | 탐지 ❌ → **설계로 유인 제거** | 탐지 ✅ 필요 |
| 시점 | MVP (P0~P4) | P5(BM) · P7(소셜)부터 |

**MVP 구간에는 위협 A만 존재한다.** 여기에 무거운 검증을 넣으면 정직한 유저만
고통받고 이탈한다 — 기록 마찰이 이탈 원인 1위라는 사실(§11 전제)과 정면으로 충돌한다.

#### 핵심 원리 2개

**① 마찰 비대칭 — 정직한 입력을 부정보다 싸게 만든다**

부정은 정직한 기록이 귀찮을 때만 매력적이다. 헬스 연동으로 운동이 자동 기입되면
"안 했는데 했다고 치기"가 오히려 **더 많은 타이핑**을 요구하게 되고, 그 순간 유인은 0에 수렴한다.
안티치트 예산의 대부분은 탐지 로직이 아니라 **기록 UX**에 써야 한다.

**② 보상 자기교정 — 거짓 입력이 스스로 벌을 준다** ★

재화로 해금하는 것이 **현실 운동을 돕는 기능**(§5.1)이므로, 입력이 거짓이면
그 보상이 자동으로 무의미해지거나 역효과를 낸다. 이 기획만 쓸 수 있는 무기다.

- 벤치 100kg 거짓 입력 → 프로그램이 다음 주 105kg 처방 → 물리적으로 불가능 → 즉시 들통
- 운동 안 하고 기록 → "정체 구간 감지, 디로드 하세요" → 쓸모없는 조언
- 식단 허위 기록 → 리포트가 엉뚱한 분석 → 본인이 먼저 답답해짐

**거짓말의 대가를 처벌이 아니라 "보상의 무가치화"로 오게 설계하면, 굳이 잡을 필요가 없다.**
Q1(§10) 시설 보상 설계 시 이 성질을 만족하는 보상을 우선한다.

#### 수단 목록

**Tier 0 — 설계로 유인 제거 (마찰 0)**

| # | 수단 | 비고 |
|---|---|---|
| 1 | 일일 획득 상한 | 몰아서 입력해도 이득 없음 |
| 2 | 누적량이 아니라 **연속성**에 보상 | 몰아치기 입력의 가치를 낮춤 |
| 3 | 소급 입력 창 제한 (24~48h) | 이후 소급분은 대폭 감액 |
| 4 | 현금성 보상 영구 배제 | 봇 유인 제거 효과가 가장 큼 (§8.3) |
| 5 | 수동 입력 지급률 차등 | 30% + 캡. **0%는 금지** |
| 6 | 스테이지 난이도를 스탯에 연동 | 치트로 얻은 우위가 곧 상쇄됨 |
| 6a | **레코드 단위 타당성 상한** | 세션 볼륨·유산소 부하·하루 세션 수. 아래 참조 |

> **시뮬레이션에서 확인된 것:** 비율 감액(수동 30%)만으로는 무제한 입력을 막지
> 못한다. 30%를 곱해도 볼륨을 5배로 적으면 그만이기 때문이다. 매일 부풀린 수치를
> 손으로 넣는 대조군이 정직한 유저를 **활동 코인 3.8배, 도달 스테이지 2.1배**로
> 앞섰다.
>
> 그래서 Tier0 에 두 가지를 더했다.
>
> - **레코드 단위 상한**(6a) — 초중급 상단을 넉넉히 잡아 정직한 기록은 걸리지 않는다
> - **빈도 기반 보상**(2의 구체화) — 코인의 주된 몫을 "며칠 했는가"에 싣는다.
>   볼륨은 부풀릴 수 있지만 일수는 부풀리기 어렵다
>
> 이후 치터의 활동 코인 우위는 3.8배 -> **1.24배**로 떨어졌다. 다만 스탯·스테이지
> 우위(1.4~2.4배)는 남는다. 매일 2세션을 조작 입력하는 **빈도**에서 오는 것이라
> 비율 감액으로는 닫히지 않고, **Tier1-9(동시간대 움직임 대조)가 반드시 필요하다.**
> MVP 채택분에 9번이 들어 있는 이유가 이것이다.


- ❌ **식단에 검증 압박** — §7.1 섭식장애 가드레일과 정면 충돌. "기록했다"에 보상하는 선에서 멈춘다
- ❌ **MVP에서 서버 기반 탐지** — P4까지 로컬 온리 전략(§9.2)이 깨진다

## 8. BM (수익 모델)

### 8.1 스택 (4단)

| 단 | 수단 | 설계 |
|---|---|---|
| 1 | **리워드 광고** | 하루 3~5회 캡. 유저가 *선택*하는 위치에만 (오프라인 보상 2배, 던전 재도전, 코인 뭉치) |
| 2 | **시즌 패스** ★ | 12주 = 현실 운동 프로그램 1사이클과 정확히 일치 |
| 3 | **프리미엄 구독** | §5.1 해금 기능을 상시 개방. **게임 진행 우위는 0** |
| 4 | **코스메틱** | 스킨·짐 테마 |

### 8.2 근거 데이터

- 리워드 광고 eCPM $16~20, 도입 시 ARPDAU 30~66% 상승, 시청자의 IAP 전환율 4배.
  다만 **방치형에서 광고 과다는 이탈 1순위 요인.**
- 구독은 모바일 게임 매출 중 2025.01 4% → 2026 초 7%로 성장 중.
- WalkScape는 MTX·광고 없이 구독만 채택하며,
  **구독자에게 재화·경험치·레벨 우위를 일절 주지 않는다.** (지역 해금만) — 참고할 선례.

### 8.3 절대 금지

- ❌ 코인·스탯 직접 판매 → "돈으로 근육 산다" = 컨셉 자살
- ❌ 스테이지 스킵권 → 운동할 이유 제거
- ❌ 토큰 / 현금 환급 (M2E)
  - STEPN은 월매출 $1억, GMT 시총 $40억에서 5개월 만에 95% 폭락.
    원인은 *걸어서 버는 토큰 > 소모되는 토큰* 인플레 구조 + 봇 파밍.
  - **현금성 보상을 넣는 순간 봇과의 전쟁이 시작된다.**

## 9. 기술 스택

### 9.1 Unity (D5)

**장점:** 오토배틀 연출, 수치 밸런싱 툴링, 시설 배치 UI 모두 강점.

**유일한 큰 마찰점 — 헬스 연동.**
Unity는 HealthKit / Health Connect 접근이 기본 제공되지 않는다. 선택지:

| 방식 | 난이도 | 비고 |
|---|---|---|
| 네이티브 플러그인 직접 작성 (Swift + Kotlin) | ★★★★☆ | 통제권 최대. 양 플랫폼 각각 작성 필요 |
| 검증된 서드파티 에셋 | ★★☆☆☆ | 유지보수·OS 업데이트 대응 리스크 |
| 헬스 연동만 네이티브 셸 + Unity as a Library | ★★★★★ | 과함. 비권장 |

> **권장:** P0에서 **네이티브 플러그인 스파이크를 최우선으로** 뚫는다.
> 여기서 막히면 전체 기획이 성립하지 않으므로, 게임 코드보다 먼저 검증한다.

### 9.2 데이터

- P4까지 **로컬 온리** (SQLite). 서버 없음 = 개인 개발에 압도적으로 유리.
- P5(BM) 시점에 영수증 검증용 최소 서버.
- P7(소셜) 시점에 본격 백엔드. 여기서부터 운영 비용 발생.

> 식단앱은 1개월 후 리텐션 30%, 50~70%가 30일 내 이탈하며 원인 1위가 기록 마찰이다.

### 11.1 시뮬레이션 현황

코어 루프는 Unity·기기 없이 돌아간다. `src/Healper.Core` 는 `UnityEngine` 참조가
없어 나중에 `Assets/` 로 그대로 옮길 수 있고, `sim` 이 그 소스를 링크해 28일치를
시드 30개 평균으로 굴린다.

```bash
dotnet run --project sim
```

숫자는 전부 `Balance.cs` 한 곳에 있다. 값을 바꿔 다시 돌리는 것이 스프레드시트
시뮬레이션을 대신한다.

**현재 지표 (꾸준한 유저 vs 방치 유저)**

| 지표 | 값 | 목표 | 판정 |
|---|---|---|---|
| 총 획득 코인 격차 | 9.1배 | 약 10배 | 🟢 |
| 도달 스테이지 격차 | 12.7배 | — | 🟢 |
| 오프라인 비중(꾸준) | 24% | 50% 미만 | 🟢 |
| 코인 잔고 / 총획득 | 11% | 싱크 부족 아님 | 🟢 |
| 치터 vs 정직 (활동 코인) | 1.24배 | 1.0배 이하 | 🟡 §7.3 참조 |
| 치터 vs 정직 (스테이지) | 1.42배 | 1.0배 이하 | 🟡 Tier1-9 필요 |

**해결된 것**

- 오프라인 수급이 활동 수급을 5배 압도하던 구조 충돌(§3) — 기본치를 활동 비례로 전환
- 지구력 스탯이 죽어 있던 문제 — 근력 40.8 대 지구력 5.3 → 26.3
- 일일 캡이 한 번도 걸리지 않던 문제 — 캡 80 → 45, 타당성 상한 추가

**남은 것**

- 치터의 스탯·스테이지 우위. 센서 교차검증(§7.3 Tier1-9)이 붙어야 닫힌다
- 위 숫자는 전부 가짜 데이터 기준이다. **P0 이후 본인 실제 기록으로 재조정할 것**

### MVP 커트라인 = P0 + P1

이 둘만 만들어 본인이 2주 써보고
**"운동 안 했는데 앱 열기가 아쉽다"는** 감정이 안 들면, P2 이후는 만들어도 소용없다.

### 난이도 함정

1. **경제 밸런싱(P1~P3)이 코딩보다 훨씬 어렵다.** 스프레드시트로 먼저 시뮬레이션할 것. 코드로 밸런싱하면 못 고친다.
2. **헬스 연동(P0)이 최대 기술 리스크.** 게임 코드보다 먼저 뚫는다.
3. **P7 소셜부터 서버 비용이 발생.** P4까지 로컬 온리로 버티는 게 개인 개발엔 훨씬 낫다.

### 확인된 시장 공백 3가지 = 차별점

1. **식단을 게임 인풋으로 받는 서비스가 사실상 없다.** 전부 걸음수/운동만.
2. **재화 → 운동·식단 기능 해금**이라는 역방향 고리를 아무도 안 한다. (§5.1)
3. WalkScape는 구조는 비슷하나 인풋이 걸음수 하나뿐이고, 역방향 고리가 없다.
